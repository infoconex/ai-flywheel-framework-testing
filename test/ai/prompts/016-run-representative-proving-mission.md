# Prompt 016 — Run Representative Proving Mission

## Purpose

Verify that the installed AI Flywheel operating model can complete one useful, representative, non-destructive mission using the full lifecycle without modifying the framework repository.

## Authorization

Use the immutable framework revision supplied by the canonical runner. Read the manifest first and every required file in manifest order. Resolve durable state, mission, and goal only as context. Construct all proving-mission artifacts in memory and label displayed artifacts `PROPOSED ONLY — NOT WRITTEN`.

Do not reuse the durable onboarding goal as authorization, inspect an application repository, persist synthetic artifacts, advance durable readiness, or modify the framework repository.

## Representative mission

Construct one synthetic mission, one goal, and one stable execution for a read-only inventory of the installed framework. The mission must explicitly authorize certification scenario 9 and the exact inventory scope.

The inventory must:

- Use the pinned immutable framework revision.
- Read the actual manifest at that revision.
- Resolve every `manifest.required_files` path exactly once.
- Record missing paths, duplicates, case collisions, and unreadable targets.
- Preserve immutable revision, exact path, and resolution result as evidence.
- Avoid application-repository inspection and repository mutation.

## Lifecycle proof

Apply all eight stages in canonical order with stable identities and complete provenance. Observations must contain inventory facts; evaluations must assess completeness and uniqueness; classification must represent validated learning when complete or a finding when incomplete; Adapt must use a schema-valid no-change disposition with an explicit reason; Validate must cover each acceptance criterion; Persist and Reuse must be proposed only; and terminal execution, goal, mission, and synthetic state must agree.

The inventory method may be assessed as reusable guidance, but no knowledge or framework change is durably written.

## Acceptance criteria

- Every manifest-required path resolves exactly once.
- Inventory evidence preserves immutable revision, exact path, and result.
- The representative mission completes without framework mutation.

Each criterion must map to independently sufficient evidence and validation.

## Required verification

Verify manifest equality, mission and goal schemas, explicit authorization, stable execution identity, lifecycle scope, evidence provenance, classification, no-change adaptation rationale, criterion validation, persistence and reuse semantics, terminal consistency, result formatting, and repository immutability.

## Negative validation

Reject at least 34 invalid cases covering incomplete or altered inventories, missing or duplicate paths, inferred revisions, unauthorized scope, unsupported observations, broken provenance, invalid no-change adaptation, incomplete criterion evidence, premature persistence or reuse claims, terminal disagreement, application inspection, and repository mutation.
