# Prompt 009 — Persist to Reuse

## Purpose

Verify, without changing the framework repository, that a valid execution can complete Persist, enter and complete Reuse, assess learning and knowledge, and close the synthetic execution under the current contracts.

The revision-specific runner supplies immutable revisions and publication details.

## Authorization

Use the pinned `Infoconex/ai-flywheel-framework` revision. Read the manifest first and all required files in order. Construct complete synthetic artifacts in memory only. Do not change the framework repository, inspect an application repository, persist records, promote knowledge, invent approval, or create alternate results.

Label every displayed artifact:

> **PROPOSED ONLY — NOT WRITTEN**

## Starting snapshot

Construct a schema-valid resumable execution/state pair where Persist is the sole in-progress stage, Execute through Validate are completed, and Reuse is pending.

Include a terminal applied persistence plan whose targets were processed in deterministic order, re-read, digest-verified, and included in successful final verification. No unplanned change or persistence blocker may remain.

Include structured reuse assessments for every material candidate learning item and every existing knowledge item considered. Assessments must record evidence and validation provenance, applicability, limitations, guidance, duplicate and conflict handling, disposition, approvals or decisions when required, and any proposed knowledge reference.

## Proposed transition and closure

Construct complete proposed artifacts showing:

- Persist completed with summary, timestamps, and the applied persistence-plan reference.
- Reuse began only after Persist and final verification completed.
- Reuse completed with all required assessment references.
- Any proposed knowledge item satisfies schema, provenance, duplicate/conflict, approval, and history rules.
- Execution closes with a permitted terminal status, completion time, outcome, disposition, and rationale.
- Every lifecycle stage is completed or justified as not applicable.
- State clears active execution and lifecycle stage and uses a supported status without inventing readiness.
- Goal and mission state change only when their completion contracts are satisfied.

No proposed artifact is written.

## Validation

Validate YAML 1.2, Draft 2020-12 schemas with formats, applied persistence semantics, final verification, Reuse entry conditions, assessment completeness, evidence and validation provenance, duplicate/conflict handling, approval boundaries, history preservation, terminal execution closure, goal and mission completion, state invariants, timestamps, and repository immutability.

## Required negative cases

Report exactly 20 deterministic rejections:

1. Reuse begins before Persist completes.
2. Reuse begins while the persistence plan is not applied.
3. Reuse begins before final verification passes.
4. A persistence blocker remains.
5. A material candidate lacks an assessment.
6. A considered knowledge item lacks an assessment.
7. An assessment lacks evidence provenance.
8. Required validation provenance is missing.
9. Applicability or limitations are missing.
10. Duplicate checks are missing.
11. Conflict checks are missing.
12. Proposed knowledge lacks actionable guidance.
13. Required approval or decision is missing.
14. Prior knowledge history is not preserved.
15. Adaptation reuse status conflicts with the assessment.
16. Reuse completes without references, summary, or timestamps.
17. Execution closes while a stage remains pending or active.
18. Terminal execution lacks outcome, disposition, rationale, or completion time.
19. State still references the closed execution or invents readiness.
20. Goal or mission completes without sufficient evidence, validation, blocker disposition, or approval.

## Result format

Produce exactly 12 numbered sections:

1. Verification Summary
2. Validation Trace
3. Starting Operating Snapshot
4. Persist Completion Decision
5. Proposed Reuse Assessments
6. Proposed Knowledge Artifacts
7. Proposed Terminal Execution Artifact
8. Proposed State Artifact
9. Schema and Invariant Results
10. Negative Validation Results
11. Framework Defects
12. Repository Mutation Confirmation

If no reusable defect exists, state exactly:

> No reusable framework defects were found during the non-persistent Persist-to-Reuse lifecycle verification.

Only the revision-specific runner may authorize writing the canonical result.
